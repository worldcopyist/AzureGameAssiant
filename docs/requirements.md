## 1. 背景与问题

用户在玩游戏、剪辑、渲染、编译或其他高负载场景下，会遇到突然的掉帧、卡顿、鼠标拖影。任务管理器与常见监控工具存在四个问题：

1. **只有现在，没有刚才**：卡顿发生后再打开工具，关键数据已经消失。
2. **只有总量，没有归因**：看得到 CPU 80%，却看不出是哪个进程、哪一类资源导致的。
3. **只有资源，没有帧**：资源占用正常也可能卡顿，缺少帧级证据就无法区分 CPU 等待、GPU 等待、显存压力与呈现节奏问题。
4. **监控本身太重**：部分工具需要注入进程、安装驱动、常驻上百 MB 内存，反而加剧卡顿。

本项目要在**不影响被观测场景**的前提下，持续记录资源数据与帧级数据，在卡顿发生时固化现场，给出可解释的归因，并可选用大模型生成更完整的分析与优化建议。

## 2. 产品定位与目标

**一句话定位**：带帧级真相与可选 AI 归因的低开销 Windows 卡顿记录仪。

| 编号 | 目标 | 衡量方式 |
| --- | --- | --- |
| G-1 | 用时间轴还原卡顿前后各 30 秒的资源与帧级全貌 | 事件发生后 2 秒内可在界面看到对应时间轴片段 |
| G-2 | 常驻开销低到用户愿意一直开着 | 浅模式采集进程 ≤ 30 MB、≤ 0.3% CPU；深模式按 NFR 预算；空闲不写盘 |
| G-3 | 给出可执行结论，而不只是曲线 | 报告包含主因分类、可疑进程、帧级证据、置信度与 1–3 条建议 |
| G-4 | 安全、透明、本地优先 | 无注入、无驱动、默认免提权；默认不联网，AI 分析仅在用户显式开启后使用 |
| G-5 | 帧级真相 | 安装权限允许时，记录 frametime、CPU/GPU 等待、显示延迟，并能定位到具体帧 |
| G-6 | AI 只做解释，不做危险操作 | AI 报告基于脱敏事实，输出结构化建议，不自动修改系统 |

**成功指标（v1.0）**

- 连续运行 8 小时无崩溃、无内存持续增长（增长 ≤ 5%）。
- 典型卡顿从发生到可在界面查看 ≤ 5 秒。
- 内置归因测试集（CPU 抢占 / 内存耗尽 / GPU 打满 / 显存不足 / 磁盘拖慢 / 系统调度停顿 / 帧节奏）分类准确率 ≥ 90%。
- 深模式下帧级数据覆盖率 ≥ 99%（目标进程运行期间）。
- 默认阈值下，10 分钟静置无误报；1 小时日常办公误报 ≤ 2 次。
- AI 报告在测试集上“主因不劣于本地规则报告”的比例 ≥ 90%，且无危险建议。

## 3. 非目标

- 不做超频、风扇曲线、电压调节。
- 不做游戏内 FPS 覆盖层；悬浮条只在桌面显示，不注入游戏。
- 不注入游戏进程、不读写游戏内存、不绕过或对抗反作弊。
- 不安装内核驱动，不要求以系统服务方式运行。
- 不做云同步、账号体系、匿名遥测。
- 不自动修改系统设置、不自动结束进程、不自动执行 AI 建议。
- 不承诺在所有反作弊环境下都能采集帧数据。
- 不支持 macOS、Linux、ARM64。

| P-4 求助者 | 想把问题发给别人看 | 一份包含时间轴、帧证据与建议的报告 |

| 编号 | 场景 | 期望行为 |
| --- | --- | --- |
| S-1 | 游戏中突然卡 2 秒 | 自动识别游戏；有权限时采集帧数据；卡顿后托盘提示；主窗口显示事件、帧证据与归因 |

| S-5 | 用户想听更完整的解释 | 在事件详情中点击“AI 分析”，预览将发送的数据，确认后获得结构化报告 |

## 5. 术语

| 术语 | 含义 |
| --- | --- |
| 采样点 | 某一时刻采集到的一组系统指标 |
| 环形缓冲 | 固定容量、写满后覆盖最旧数据的循环缓冲区 |
| 会话 | 一次卡顿事件前后各 30 秒的完整数据文件 |
| 卡顿事件 | 由帧信号、资源信号或手动标记确认的一次异常时间段 |
| 归因 | 根据事件窗口内的帧、进程与资源数据推断主因 |
| 帧级真相 | 来自呈现路径的逐帧数据：frametime、CPU/GPU 等待、显示延迟等 |
| 浅模式 | 普通权限运行，只有系统指标与启发式判定，没有帧级数据 |
| 深模式 | 以管理员权限或 Performance Log Users 组运行，启用 PresentMon 帧采集 |
| 帧尖峰 | 单帧 frametime 显著高于滚动中位数，或显示间隔出现异常空洞 |
| 厂商传感器 | 通过 NVML / ADL / IGCL 读取的温度、功耗、频率、显存等原生指标 |
| 传感器边车 | 可选进程 `AzureGameAssistant.Sensors.exe`，封装 LibreHardwareMonitorLib |
| 事实层 | 由本地代码从会话中提取的结构化证据，是 AI 的唯一输入 |
| AI 分析 | 调用用户配置的 OpenAI 兼容接口，对事实层做解释与建议 |
| BYOK | Bring Your Own Key，用户自带模型 API Key |
| 脱敏 | 移除或替换用户名、路径、机器名、IP、窗口标题等不必要信息 |
| 采集进程 | `AzureGameAssistant.Collector.exe`，无窗口后台进程 |
| 界面进程 | `AzureGameAssistant.exe`，托盘 / 悬浮条 / 主窗口 |

### 6.2 需求详情

#### FR-001 后台常驻与开机自启

- **描述**：用户登录后自动启动托盘与采集进程，不弹出主窗口；用户可在设置中关闭自启。
- **规则**：
  - 自启通过 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 注册，不写系统级启动项。
  - 采集进程无窗口、无任务栏图标；界面进程仅显示托盘图标。
  - 托盘菜单提供“退出”，退出时先停止采集并刷新会话文件。
- **验收**：重启系统后 5 秒内托盘图标出现、采集进程存在；关闭自启后重启不再自动运行；退出后无残留进程。

#### FR-002 系统指标采集

- **描述**：持续采集下列系统级指标，并与采样时间戳一一对应。
- **指标**：

| 指标 | 单位 | 说明 |
| --- | --- | --- |
| CPU 总利用率 | % | 优先使用 `% Processor Utility`，回退 `% Processor Time` |
| CPU 有效频率 | % | 相对基准频率的性能百分比 |
| 内存可用量 | MB | Available MBytes |
| 已提交量 / 提交上限 | MB | 判断提交压力与页面文件压力 |
| 页面文件使用率 | % | Paging File `% Usage` |
| 硬缺页速率 | 次/秒 | Pages Input/sec |
| 磁盘总占用率 | % | PhysicalDisk `% Disk Time` |
| 磁盘平均响应 | ms | Avg. Disk sec/Transfer |
| 系统处理器队列 | 个 | Processor Queue Length |
| 全局定时器抖动 | ms | 16ms 高精度定时器的实际延迟 |

- **规则**：常规 1 秒采样一次；游戏模式 200 毫秒采样一次。200ms 采样只更新轻量指标（CPU、内存、抖动、前台进程），磁盘与进程排行仍按 1 秒更新。
- **验收**：CPU / 内存与任务管理器偏差 ≤ 5%；时间戳严格单调递增；游戏模式连续 10 分钟无采样缺口（允许 ≤ 0.1% 丢点）。

#### FR-003 GPU 与显存采集（PDH + 厂商边车）

- **描述**：采集 GPU 总占用、每进程 GPU 占用、专用显存与共享显存；深度模式下增加温度、功耗、频率、风扇等厂商原生指标。
- **规则**：
  - M1 使用 PDH `GPU Engine` 与 `GPU Adapter Memory` / `GPU Process Memory` 计数器，支持多适配器。
  - 每进程 GPU 占用按 `pid` 聚合 3D / Copy 引擎，单进程上限按 100% 归一。
  - M3 增加可选传感器边车 `AzureGameAssistant.Sensors.exe`，基于 LibreHardwareMonitorLib，仅启用 GPU 硬件组，由它调用 NVML / ADL / IGCL。
  - 边车默认关闭；开启后独立计量内存与 CPU，不计入采集进程 30MB 红线。
  - 不加载 LHM 的 CPU/主板内核驱动；若检测到驱动加载或初始化异常，立即停止边车并在界面提示。
  - 任一厂商初始化失败时自动降级为 PDH 数据，界面缺失字段显示“—”，不得崩溃或阻塞采样。
  - 厂商 SDK 调用固定在 1 秒节拍，单次调用超过 200ms 则判定该厂商数据降级并退避 10 秒。
- **验收**：GPU 总占用与任务管理器偏差 ≤ 10%；混合显卡（核显 + 独显）能分别显示；拔掉独显或驱动异常时仍可运行；边车温度/功耗数值与厂商工具偏差 ≤ 5%；边车关闭时采集进程与浅模式一致。

#### FR-004 进程级资源排行

- **描述**：每个 1 秒采样点记录 CPU、GPU、专用工作集、IO 排名前 5 的进程；前台进程始终包含。
- **规则**：
  - 记录 PID、进程名、启动时间（用于识别 PID 复用）、CPU%、GPU%、工作集、私有字节、IO 速率。
  - 无法读取的受保护进程显示为“受保护进程”，不因此中断采集。
  - 进程名截断到 64 字符，避免超长路径。
- **验收**：排行结果与任务管理器同口径偏差 ≤ 10%；PID 复用不会把新旧进程数据混在一起；单次进程采样耗时 ≤ 10ms。

#### FR-005 实时时间轴

- **描述**：以时间为横轴，叠加 CPU、GPU、内存、显存、磁盘、frametime 等曲线；卡顿事件以标记形式落在时间轴上，点击可查看窗口内详情。
- **规则**：
  - 数据窗口默认 15 分钟，支持 1 / 5 / 15 分钟缩放与拖动。
  - CPU、GPU、内存、显存、磁盘各自使用独立折线图，共用同一时间轴与交互；默认显示 CPU / GPU / 内存 / 显存，磁盘默认关闭。
  - 每个折线图可单独开关，开关持久化并立即生效；至少保留一个可见图表，只有一张可见时自动占满宽度。
  - 内存图按提交占比（已提交 / 提交上限）绘制；显存图按 MB 绘制并自动缩放纵轴；磁盘图按 `% Disk Time` 绘制。
  - 帧级数据以独立子轨或叠加层展示；无帧数据时明确标注“浅模式”。
  - 悬停显示当前图表指标的即时值；鼠标滚轮缩放、拖动平移、双击回到实时状态。
  - 数据降采样采用每像素列 min/max，保证尖峰不被抹掉。
  - 主窗口最小化或隐藏时停止图表渲染，恢复时补绘。
- **验收**：15 分钟数据首次渲染 ≤ 300ms；缩放/拖动交互响应 ≤ 100ms；悬停数值与原始采样点一致；帧轨与系统轨在同一事件上时间对齐误差 ≤ 16ms；隐藏时 UI 进程 CPU 占用 ≤ 0.1%；单图开关后 300ms 内完成重排且设置落盘。

#### FR-006 卡顿判定

- **描述**：融合帧信号与资源信号判定卡顿，并支持全局热键手动标记。有帧数据时以帧信号为主，无帧数据时退回启发式信号。
- **信号与默认阈值**：

| 信号 | 默认阈值 | 说明 |
| --- | --- | --- |
| 帧尖峰 | 单帧 frametime ≥ max(2.5 × 最近 120 帧中位数, 50ms) | 深模式主信号 |
| 显示间隔空洞 | 相邻显示间隔 ≥ 100ms | 深模式，捕获呈现/显示链路问题 |
| 定时器抖动 | 单次 ≥ 50ms 记疑似；≥ 100ms 直接确认 | 浅模式主信号 |
| CPU 尖峰 | 前台进程 ≥ 2.5 倍基线且 ≥ 30% 单核；系统 ≥ 85% | 基线为最近 30 秒中位数 |
| GPU 尖峰 | GPU 总占用 ≥ 85% 且较基线上升 ≥ 20 个百分点 | 需 GPU 数据可用 |
| 内存压力 | 可用内存 < max(1GB, 8%) 或提交率 > 90% | 两者任一 |
| 磁盘压力 | 平均响应 ≥ 50ms 或占用率 ≥ 95% 持续 2 秒 | 参与评分，默认不单独确认 |

- **规则**：
  - 3 秒内出现的多个信号合并为同一事件；事件结束后静默 2 秒再结束；冷却 5 秒内不重复建事件。
  - 事件包含开始时间、结束时间、持续时长、综合评分（0–100）、命中的信号、峰值帧与帧统计。
  - 深模式下，帧尖峰可以单独确认事件；浅模式下仍要求至少两个资源信号或抖动直接确认。
  - 手动热键标记必然生成事件，评分记为 100，来源标记为“手动”。
  - 阈值全部可在设置中调整，修改后立即生效。
- **验收**：用测试工具制造 CPU 满载、内存耗尽、GPU 满载、磁盘高延迟，每种场景检出率 ≥ 90%；深模式下人为制造 100ms 帧尖峰检出率 100%；10 分钟静置 0 误报；事件从发生到界面可读 ≤ 2 秒。

#### FR-007 会话记录与回放

- **描述**：事件确认后，把事件前后各 30 秒数据写成一个会话文件；用户可在界面中重新打开回放。
- **规则**：
  - 文件格式为 gzip 压缩的 JSONL；包含头部元信息、系统采样、进程采样、帧采样（如有）、事件、归因报告、可选的 AI 报告、尾部校验。
  - 帧采样按批次写入，避免每帧一行造成过大开销；批次内字段使用短名与数组。
  - 先写临时文件，`FlushFileBuffers` 后原子重命名；异常退出不得留下被识别为有效会话的半文件。
  - 会话目录 `%LOCALAPPDATA%\AzureGameAssistant\sessions\`，最多保留 20 个文件或 500MB，超出按时间淘汰。
  - 同一事件重复触发时只保存一次。
  - 会话头部记录权限模式、PresentMon 版本、厂商边车状态，回放时如实展示数据缺口。
- **验收**：卡顿后 3 秒内文件可被列表发现；文件可被工具重新打开且时间轴一致；有帧数据时会话包含帧批次并可复现帧尖峰；人为强杀进程后目录中无损坏会话；留存策略生效。

#### FR-008 归因报告

- **描述**：对事件窗口内的数据做归因，给出主因分类、可疑进程、帧级证据、置信度与建议。
- **主因分类**：CPU 抢占、GPU 瓶颈、显存不足、内存压力、磁盘瓶颈、系统调度/驱动、帧节奏/呈现、着色器编译、资产流送、热降频、未知。
- **规则**：
  - 可疑进程按 CPU / GPU / 内存 / IO 的变化幅度加权排序，最多列 3 个。
  - 有帧数据时，必须给出 CPU 等待、GPU 等待、显示延迟的窗口统计，并说明主因与帧证据是否一致。
  - 结论必须基于事件窗口数据，使用“疑似 / 可能”等限定词，不得给出无证据的断言。
  - 建议为 1–3 条，可执行且不包含自动修改系统的操作。
  - 报告随界面语言生成中文或英文。
  - AI 报告与本地规则报告分开展示；AI 不可用时本地报告始终可用。
- **验收**：内置 7 类归因测试场景分类准确率 ≥ 90%；报告不含空结论（“未知”也必须给出下一步排查建议）；报告可在会话回放中复现；深模式报告必须引用至少一条帧级证据。

#### FR-009 全局热键标记

- **描述**：默认 `Ctrl+Alt+M`，用户可修改；按下后立即把“此刻之前 30 秒 + 之后 30 秒”保存为手动事件。
- **规则**：注册失败（冲突）时在设置中提示并允许改键；游戏全屏独占可能拦截系统热键，需在帮助中说明该限制。
- **验收**：桌面与无边框全屏游戏中热键有效；冲突时给出明确提示；连续按 3 次生成 3 个独立事件（受冷却合并规则约束）。

#### FR-010 游戏自动识别

- **描述**：识别前台全屏程序，自动进入 200ms 高频采样；深模式下同时启动该进程的帧采集。退出全屏 10 秒后恢复 1 秒并停止帧采集。
- **规则**：
  - 判定组合：`SHQueryUserNotificationState` 返回 `QUNS_RUNNING_D3D_FULL_SCREEN`，或前台窗口覆盖所在显示器 ≥ 95% 且进程不是桌面/任务栏/系统外壳。
  - 内置浏览器、视频播放器排除名单，避免网页全屏视频误判；用户可在设置中增删名单。
  - 切换状态不打断已有事件，不重启采集进程。
  - 目标进程切换时，PresentMon 会话平滑重启；旧会话数据保留到事件窗口结束。
- **验收**：主流游戏（至少 5 款，覆盖 DX11 / DX12 / 无边框窗口）识别率 ≥ 90%；浏览器全屏视频不触发；桌面右键全屏窗口不误判；切换游戏后 5 秒内恢复帧采集。

#### FR-011 托盘与通知

- **描述**：托盘图标常驻，悬停显示实时 CPU / GPU / 内存；右键菜单包含：打开主界面、标记卡顿、暂停/恢复监控、桌面悬浮窗开关、静音通知、设置、退出。
- **规则**：卡顿事件使用托盘气泡提示，点击打开事件详情；可在设置中关闭通知；通知内容不包含进程完整路径等敏感信息；窗口、可执行文件与托盘使用统一的多尺寸 ICO 图标。
- **验收**：菜单项状态与监控状态一致；暂停后不再产生新事件但保留已有数据；退出后托盘图标消失。

#### FR-012 桌面悬浮数据窗

- **描述**：提供可选的置顶迷你数据窗，以最简单的纵向列表显示在桌面角落；M1 只显示数值，不绘制迷你曲线，不注入游戏。
- **内容**：FPS、平均帧、1% Low、CPU、GPU、GPU 温度、内存、显存；无帧数据或温度数据时显示“—”。每项可单独开关，显存默认关闭。
- **规则**：
  - 位置支持左上 / 右上 / 左下 / 右下四角，并可分别设置水平、垂直偏移（0–4000 像素）。
  - 鼠标穿透、不抢焦点、不出现在任务栏与 Alt+Tab；不响应点击与滚轮。
  - 与主窗口共用刷新节拍；主窗口隐藏到托盘后仍持续更新。
  - 设置页和托盘菜单均可开关悬浮窗，状态持久化。
  - 仅支持主显示器（M3 增强再补多显示器位置记忆、拖动与透明度）。
  - 关闭时立即释放置顶窗口资源。
- **验收**：开启后界面进程内存增量 ≤ 8MB；四角与偏移设置保存后立即生效；鼠标点击可穿透到下方窗口；不抢占游戏焦点；关闭后无残留置顶窗口；主窗口隐藏时数值持续刷新。

#### FR-013 中英双语与明暗主题

- **描述**：界面支持简体中文与英文运行时切换；主题支持跟随系统、浅色、深色。
- **规则**：所有界面文案走资源文件，不硬编码；语言与主题切换无需重启；默认跟随系统，视觉风格极简，仅保留曲线、数值、事件列表必要元素。
- **验收**：两种语言下无缺失文案；切换语言/主题 ≤ 300ms；系统切换深浅色后 1 秒内界面跟随。

#### FR-014 设置管理

- **描述**：设置项包括采样频率、卡顿阈值、热键、开机自启、会话留存、语言、主题、通知、游戏排除名单、帧采集模式、厂商传感器开关、折线图开关、桌面悬浮窗（开关、位置、偏移、内容项）、AI 供应商与预算。
- **规则**：保存为 `%LOCALAPPDATA%\AzureGameAssistant\settings.json`，带 `schemaVersion`；文件损坏时备份原文件并回退默认值，不得阻止启动。
- **验收**：修改即时生效（标注需重启的除外）；损坏设置文件可自动恢复；默认值与本文档一致；API Key 不出现在设置文件中。

#### FR-015 报告导出

- **描述**：把单个会话导出为 Markdown 报告与时间轴 PNG 截图；可选附带 AI 报告。
- **规则**：导出完全本地，由用户选择保存路径；文件名包含事件时间与主因；报告包含环境摘要、事件时间轴、指标峰值、帧统计、可疑进程、建议、数据缺口说明。
- **验收**：导出的 Markdown 在常见编辑器可正常显示；PNG 包含时间轴、事件标记与帧轨；导出后无网络请求。

#### FR-016 日志与诊断

- **描述**：采集进程、界面进程、传感器边车分别写滚动日志，保留最近 5 个文件、每个 2MB；设置中提供“打开日志目录”。
- **规则**：默认 Info 级别；不记录进程完整路径、用户名、IP、API Key、AI 请求体；写盘失败不得影响采集。
- **验收**：日志可定位启动、降级、错误原因；滚动策略生效；关闭日志后不再写盘；日志中检索不到 API Key。

#### FR-017 单实例与异常恢复

- **描述**：采集进程、界面进程、传感器边车各保证单实例；界面进程检测到采集进程退出时自动重启（退避 1s / 5s / 15s，最多 3 次）。
- **规则**：使用命名互斥体；采集进程崩溃时写入崩溃摘要；重启后环形缓冲从空开始，不拼接损坏数据；边车崩溃只影响厂商传感器，不影响帧与系统采集。
- **验收**：重复启动只保留一个实例；强杀采集进程后 5 秒内恢复采集；连续失败 3 次后停止重试并在界面提示；强杀边车后 10 秒内自动恢复或明确降级。

#### FR-018 权限降级

- **描述**：默认以普通用户权限运行；部分受保护进程、帧采集或厂商数据不可用时，功能降级但不崩溃。
- **规则**：
  - 默认浅模式：系统指标 + 启发式判定，不要求管理员权限。
  - 深模式：用户显式选择“以管理员身份重启”后，界面与采集进程同权限运行，并启用 PresentMon。
  - 界面顶部显示当前模式、缺失能力与升级入口；不得自动提权，不得弹出 UAC 骚扰。
  - 提供“加入 Performance Log Users 组”的文字说明，允许用户免每次 UAC 获得帧数据。
- **验收**：普通权限下完成核心采集与启发式归因；受保护进程显示占位信息；提权重启后帧数据出现；混合权限场景给出明确提示；拒绝 UAC 后保持浅模式且不崩溃。

#### FR-019 帧级真相采集

- **描述**：通过随包分发的 Intel PresentMon 控制台程序采集目标进程的逐帧数据，并与系统采样对齐。
- **数据项**：frametime、瞬时 FPS、1% low、0.1% low、CPU busy/wait、GPU latency/busy/wait、显示延迟、动画误差、呈现模式、丢帧标记。
- **规则**：
  - 只对前台游戏或用户手动指定的进程采集，默认不对全系统采集。
  - 使用 PresentMon 官方可执行文件，不注入、不 Hook、不自研 ETW consumer。
  - PresentMon 版本锁定并校验 SHA256；参数与列名以随包版本的 `--help` 为准。
  - 帧数据进入独立环形缓冲（至少 3 分钟），事件确认后截取前后各 30 秒写入会话。
  - 相邻显示间隔出现 ≥ 100ms 空洞时记为帧尖峰，即使 frametime 正常。
  - 权限不足、PresentMon 启动失败、目标进程退出时，降级为浅模式并记录原因。
  - 深模式下额外 CPU 开销 ≤ 1.0%，PresentMon 子进程工作集 ≤ 60MB。
- **验收**：DX11 / DX12 / 无边框窗口各至少 1 款游戏采集成功；帧轨与系统轨时间对齐误差 ≤ 16ms；1% low / 0.1% low 与 CapFrameX 同场对比偏差 ≤ 5%；强杀 PresentMon 后 10 秒内重启或明确降级；浅模式不会因缺少帧数据报错。

#### FR-020 LLM 深度分析

- **描述**：用户可为单个事件请求大模型分析；模型基于本地生成的事实层输出结构化报告与设备优化建议。
- **规则**：
  - 供应商采用 **OpenAI 兼容接口**（`/v1/chat/completions`），支持 OpenAI、DeepSeek、通义千问兼容模式、智谱、Moonshot、SiliconFlow、Ollama、LM Studio 与自定义 Base URL。
  - 用户自带 API Key（BYOK）；Key 存入 Windows Credential Manager，不写入 `settings.json`、日志或会话文件。
  - 默认**手动触发**；可选“严重事件自动分析”，必须设置每日预算与每月上限，默认关闭。
  - 发送前必须展示将要发送的 JSON 预览；默认发送脱敏后的事实摘要，用户可显式选择“包含完整会话数据”。
  - 事实层包含：环境摘要、事件与信号、指标峰值、Top 进程、帧统计、数据缺口、已启用的传感器。不包含窗口标题、命令行、完整路径、用户名、IP、机器名。
  - 模型必须返回严格 JSON：`summary`、`primaryCause`、`confidence`、`evidence[]`、`suspects[]`、`frameAnalysis`、`recommendations[]`、`limitations`、`disclaimer`。
  - 每条建议包含 `action`、`risk`（low/medium/high）、`expectedEffect`、`howTo`；禁止建议关闭安全软件、修改系统关键设置或执行未知脚本。
  - JSON 校验失败时自动修复一次；仍失败则回退本地规则报告，并保留原始响应供诊断（不含密钥）。
  - 支持流式输出与取消；超时 60 秒；429/5xx 退避重试 1 次，401/403 不重试并提示检查 Key。
  - 输出语言跟随界面语言；本地模型（Ollama / LM Studio）走同一接口，可完全离线。
  - AI 报告保存在本地，与会话关联；用户可删除，删除会话时一并删除。
- **验收**：至少 3 家云供应商 + 1 个本地模型完成联调；JSON 校验通过率 ≥ 98%；断网、超时、401、429 均有可读提示；AI 不可用时本地报告仍可生成；测试集中无危险建议；每日预算触发后停止请求。

#### FR-021 AI 隐私、成本与安全

- **描述**：AI 功能默认关闭，所有联网行为必须可见、可控、可审计。
- **规则**：
  - 首次开启需阅读并确认隐私说明；更换供应商或 Base URL 需重新确认。
  - 每次请求前展示：供应商、模型、目标地址、预计输入/输出 token、预计费用、脱敏后的请求预览。
  - 脱敏默认开启：移除用户目录、盘符路径、机器名、用户名、IP/MAC、窗口标题、命令行；进程名可选哈希或保留。
  - 不在请求中发送 API Key 之外的任何凭证；不在 URL 查询参数中放 Key。
  - 强制 HTTPS（本地回环地址除外）；拒绝明文 HTTP 远程地址。
  - 不发送遥测、崩溃报告或使用统计；不自动重发失败请求。
  - 输出按不可信内容处理：Markdown 渲染禁用原始 HTML、远程图片与 `javascript:` 链接；不执行任何命令。
  - 提示词注入防护：事实数据放在明确分隔的数据区，系统提示要求忽略数据中的指令；进程名等外部字符串做转义与长度限制。
  - 成本控制：按字符数估算 token；显示本次与当日累计；达到预算硬停止；预算与用量仅存本地。
- **验收**：默认配置下抓包无任何外发请求；开启后请求仅发往用户确认的地址；日志/设置/会话中检索不到 Key；恶意进程名无法改变模型指令；达到预算后不再发起请求；删除会话后 AI 报告同时删除。

| NFR-P-02 | 采集进程平均 CPU | ≤ 0.3%（浅）/ ≤ 0.5%（深，采集进程自身） | 整机逻辑处理器为分母；不含 PresentMon 子进程 |

| NFR-P-10 | 传感器边车 | 工作集 ≤ 35 MB；CPU ≤ 0.2% | 仅 GPU 硬件组，1 秒节拍 |

### 7.2 兼容性

- Windows 10 1909 / 20H2 / 21H2 / 22H2 与 Windows 11 22H2 及以上，x64。
- 多显示器、DPI 100%–200%，Per-Monitor V2。
- NVIDIA / AMD / Intel 核显与独显；无独显、驱动异常、混合显卡均可运行。
- 不依赖 .NET 运行时（界面自包含发布，采集 NativeAOT，边车随包自带运行时）。
- 不依赖任何厂商额外安装的运行时（厂商 DLL 由驱动自带，动态加载）。
- 深模式需要 PresentMon 支持的系统版本；不支持时保持浅模式。

### 7.3 可靠性

- 连续运行 8 小时无崩溃；24 小时压测内存增长 ≤ 5%。
- 句柄数稳定（±10 个）；无线程泄漏。
- 会话写入原子化；断电或强杀不得产生“有效但损坏”的会话。
- 采集进程崩溃后由界面进程自动恢复，失败 3 次后停止并提示。
- PresentMon 或传感器边车崩溃不得导致采集主进程退出。

### 7.4 隐私

- 默认不发起任何网络请求（含更新检查、遥测、崩溃上报）。
- AI 分析为可选功能，默认关闭；首次使用需显式同意，并在每次请求前展示脱敏后的发送内容。
- 仅采集性能指标、进程名、PID、启动时间、帧时间；不采集窗口标题、命令行、文件内容、用户名、IP。
- 发送给模型的数据遵循最小必要原则；默认不发送原始会话文件。
- API Key 仅存 Windows Credential Manager，不进入设置、日志、会话与导出报告。
- 数据仅存本机；导出与分享由用户主动操作。
- 提供“清除所有会话、AI 报告与设置”入口。

### 7.5 安全

- 不注入、不 Hook、不加载驱动、不读写其他进程内存。
- 帧采集仅调用 PresentMon 官方可执行文件，不修改游戏或驱动。
- 命名管道与共享内存 ACL 仅允许当前用户访问，拒绝远程客户端。
- 默认 `asInvoker`；提权必须由用户显式触发，且界面与采集进程同权限。
- 所有外部输入（会话文件、设置文件、AI 响应、CSV）做长度与类型校验，损坏文件只拒绝加载，不执行内容。
- AI 输出按不可信内容处理，禁止渲染原始 HTML、远程资源与可执行链接。
- 第三方二进制固定版本、校验哈希、附带许可证声明。

### 7.6 可用性与可访问性

- 中文 / 英文运行时切换，默认跟随系统语言。
- 明暗主题跟随系统，支持手动覆盖。
- 关键操作提供键盘可达路径与 AutomationProperties 名称。
- 托盘与悬浮条不阻塞主界面；所有长操作（含 AI 请求）可取消。
- 浅/深模式、帧数据缺失、AI 不可用均有明确但不打扰的提示。

### 7.7 可维护性

- 采集、帧解析、判定、存储、AI、UI 分层，核心算法可脱离 UI 单测。
- 所有阈值集中配置，不散落在代码中。
- 第三方依赖集中登记，版本与许可证可审计。
- 提交、分支、Issue、PR 遵守提交规范；每个任务结束更新交接文档。

## 9. 性能验收方法

1. 使用 Release 构建，关闭调试器、关闭 Visual Studio 诊断工具。
2. 测量环境：Windows 11 最新正式版，SSD，至少 8 逻辑处理器；记录 CPU / GPU / 内存型号。
3. 内存：稳定运行 10 分钟后，用 PowerShell 读取 `WorkingSet64` 与 `PrivateMemorySize64`，重复 3 次取中位数；以专用工作集为准。
4. CPU：记录 10 分钟内 `TotalProcessorTime` 增量，按 `增量 / 实际时长 / 逻辑处理器数 × 100%` 计算整机占比。
5. 磁盘：用性能监视器记录进程 `IO Write Bytes/sec`，静置 10 分钟取平均。
6. 游戏模式：用至少 2 款游戏各运行 10 分钟，分别测量浅模式与深模式；同时确认无采样缺口。
7. 帧开销：深模式下对比开启/关闭 PresentMon 的整机 CPU 与游戏平均 FPS，确认额外开销 ≤ 1.0%、FPS 下降 ≤ 2%。
8. 边车：开启厂商传感器后单独测量 `AzureGameAssistant.Sensors.exe` 的内存与 CPU。
9. AI：用固定测试集测量首字节与完整响应时间；记录输入/输出 token 与估算费用；确认预算硬停止。
10. UI 内存：分别测量“仅托盘”“悬浮条开启”“主窗口显示 15 分钟数据”“AI 报告打开”四种状态。
11. 任何一项超出 NFR 目标即视为不通过，须在发布前修复或在交接文档中记录豁免理由。

## 11. 验收标准

**M1 出口**

- 主窗口能显示 15 分钟 CPU / GPU / 内存 / 磁盘曲线，悬停可读到同一时刻的进程排行。
- 采集进程 ≤ 30MB / 0.3% CPU；界面进程 ≤ 80MB；空闲无会话写盘。
- 托盘、自启、设置、日志、单实例、权限降级均可用。
- 连续运行 30 分钟无崩溃、无采样中断。

**M2 出口**

- 深模式下至少 3 款游戏采集到帧数据；帧轨与系统轨对齐；1% low 对比偏差 ≤ 5%。
- 帧信号 + 资源信号 + 热键可用；7 类测试场景检出率 ≥ 90%；10 分钟静置 0 误报。
- 事件自动保存前后各 30 秒；有帧数据时会话可完整回放。
- 归因报告包含主因、可疑进程、帧证据、置信度、建议；中英文均无缺失文案。
- 游戏自动识别在 5 款游戏中 ≥ 90%，浏览器全屏视频不误判。

**M3 出口**

- NVIDIA / AMD / Intel 三家传感器至少各自在对应硬件上验证一次；边车关闭/崩溃时降级正常。
- AI 分析至少 3 家云供应商 + 1 个本地模型联调；默认零外发；预算与脱敏生效。
- 悬浮条、Markdown + PNG 导出、留存清理可用。
- 全部 NFR 指标通过测量；便携 ZIP 解压即用。
- 交接文档、开发文档、第三方许可证清单与实际实现一致。

## 12. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| PDH GPU 计数器在不同驱动/系统上实例名与精度不一致 | GPU 曲线缺失或偏差大 | 以 English counter 名注册；解析失败时降级为“不可用”；M3 用厂商边车补足 |
| PresentMon 需要管理员权限 | 普通用户无帧数据 | 浅/深模式；显式提权入口；Performance Log Users 说明；绝不自动提权 |
| PresentMon 上游参数/列名变化 | 帧采集失败 | 锁定版本 + SHA256；表头映射；启动自检；失败降级浅模式 |
| 反作弊对 ETW 敏感 | 用户账号顾虑 | 不注入、不 Hook、不读写内存；只运行官方 PresentMon；明确不承诺全兼容 |
| 厂商 SDK（NVML / ADL / IGCL）接口或 DLL 随驱动变化 | 边车初始化失败 | LHM 封装 + 动态降级；独立进程隔离；200ms 超时与退避 |
| LHM 触发内核驱动 | 违反“无驱动”承诺 | 仅 GPU 硬件组；启动后检查驱动；检测到即停边车并提示 |
| 帧数据量过大 | 内存/会话超预算 | 独立 3 分钟环形缓冲；会话按批次压缩；事件窗口外不落盘 |
| 卡顿判定误报/漏报 | 用户不信任结论 | 帧优先 + 多信号 + 阈值可调；建立回归测试集；报告标注数据缺口 |
| 内存红线 30MB 难以达成 | 违反核心卖点 | AOT、预分配、NT API、GPU 通配符 1 秒一次；帧解析缓冲区复用；预算测试卡 PR |
| WPF 界面内存超 80MB | 违反体验目标 | 自绘图表、隐藏停渲染、限制历史缓存、AI 响应流式解析 |
| LLM 幻觉或危险建议 | 误导用户 | 事实层约束、结构化 schema、危险建议过滤、免责声明、本地报告兜底 |
| LLM 隐私泄露 | 用户信任受损 | 默认关闭、默认脱敏、发送前预览、显式同意、可完全本地 |
| LLM 成本失控 | 用户费用增加 | 手动默认、token 估算、每日/每月预算、硬停止、不自动重试 |
| 提示词注入（恶意进程名等） | 模型偏离任务 | 数据分隔、转义、指令隔离、输出校验、不执行输出内容 |
| 第三方许可证不合规 | 法律风险 | 固定版本、保留声明、第三方清单、CI 检查（M3） |
