## 1. 背景与问题

用户在玩游戏、剪辑、渲染、编译或其他高负载场景下，会遇到突然的掉帧、卡顿、鼠标拖影。任务管理器与常见监控工具存在三个问题：

1. **只有现在，没有刚才**：卡顿发生后再打开工具，关键数据已经消失。
2. **只有总量，没有归因**：看得到 CPU 80%，却看不出是哪个进程、哪一类资源导致的。
3. **监控本身太重**：部分工具需要注入进程、安装驱动、常驻上百 MB 内存，反而加剧卡顿。

本项目要在**不影响被观测场景**的前提下，持续记录资源数据，在卡顿发生时固化现场，并给出可执行的归因结论。

## 2. 产品定位与目标

**一句话定位**：纯本地、低开销的 Windows 卡顿记录仪与归因器。

| 编号 | 目标 | 衡量方式 |
| --- | --- | --- |
| G-1 | 用时间轴还原卡顿前后各 30 秒的资源全貌 | 事件发生后 2 秒内可在界面看到对应时间轴片段 |
| G-2 | 常驻开销低到用户愿意一直开着 | 采集进程 ≤ 30 MB、≤ 0.3% CPU；空闲不写盘 |
| G-3 | 给出可执行结论，而不只是曲线 | 报告包含主因分类、可疑进程、置信度与 1–3 条建议 |
| G-4 | 安全、透明、纯本地 | 无网络请求、无注入、无驱动、默认免提权 |

**成功指标（v1.0）**

- 连续运行 8 小时无崩溃、无内存持续增长（增长 ≤ 5%）。
- 典型卡顿从发生到可在界面查看 ≤ 5 秒。
- 内置归因测试集（CPU 抢占 / 内存耗尽 / GPU 打满 / 磁盘拖慢 / 系统调度停顿）分类准确率 ≥ 90%。
- 默认阈值下，10 分钟静置无误报；1 小时日常办公误报 ≤ 2 次。

## 3. 非目标

- 不做超频、风扇曲线、电压调节。
- 不做游戏内 FPS 覆盖层，v1.0 不采集逐帧呈现时间。
- 不注入游戏进程、不读写游戏内存、不绕过或对抗反作弊。
- 不安装内核驱动，不要求以系统服务方式运行。
- 不做云同步、账号体系、匿名遥测。
- 不支持 macOS、Linux、ARM64。
- 不自动修改系统设置或结束进程，只给建议。

## 4. 用户与场景

| 角色 | 描述 | 关注点 |
| --- | --- | --- |
| P-1 玩家 | 玩 3A / 网游，偶发掉帧 | 哪一秒卡的、是不是后台程序抢资源、显存是否爆了 |
| P-2 创作者 | 剪辑、渲染、编译时卡顿 | 是 CPU、内存还是磁盘瓶颈，换硬件是否有用 |
| P-3 排障者 | 电脑整体发涩但找不到原因 | 系统级停顿、驱动/调度问题、内存压力 |

| 编号 | 场景 | 期望行为 |
| --- | --- | --- |
| S-1 | 游戏中突然卡 2 秒 | 自动识别游戏并高频采样；卡顿后托盘提示；主窗口显示事件与归因 |
| S-2 | 剪辑预览卡顿 | 记录卡顿窗口，指出是 CPU 编码、显存不足还是磁盘读取慢 |
| S-3 | 桌面整体卡顿 | 定时器抖动检测生效，即使资源占用不高也能记录系统级停顿 |
| S-4 | 事后求助 | 导出 Markdown 报告 + 时间轴截图，发给他人查看 |

## 5. 术语

| 术语 | 含义 |
| --- | --- |
| 采样点 | 某一时刻采集到的一组系统指标 |
| 环形缓冲 | 固定容量、写满后覆盖最旧数据的循环缓冲区 |
| 会话 | 一次卡顿事件前后各 30 秒的完整数据文件 |
| 卡顿事件 | 由三重信号或手动标记确认的一次异常时间段 |
| 归因 | 根据事件窗口内的进程与资源数据推断主因 |
| 游戏模式 | 自动识别到全屏游戏后启用的 200ms 高频采样状态 |
| 采集进程 | `AzureGameAssistant.Collector.exe`，无窗口后台进程 |
| 界面进程 | `AzureGameAssistant.exe`，托盘 / 悬浮条 / 主窗口 |

### 6.2 需求详情

#### FR-001 后台常驻与开机自启

- **描述**：用户登录后自动启动托盘与采集进程，不弹出主窗口；用户可在设置中关闭自启。
- **规则**：
  - 自启通过 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 注册，不写系统级启动项。
  - 采集进程无窗口、无任务栏图标；界面进程仅显示托盘图标。
  - 托盘菜单提供"退出"，退出时先停止采集并刷新会话文件。
- **验收**：重启系统后 5 秒内托盘图标出现、采集进程存在；关闭自启后重启不再自动运行；退出后无残留进程。

#### FR-002 系统指标采集

- **描述**：持续采集下列系统级指标，并与采样时间戳一一对应。
- **指标**：

| 指标 | 单位 | 说明 |
| --- | --- | --- |
| CPU 总利用率 | % | 优先使用 `% Processor Utility`，回退 `% Processor Time` |
| CPU 有效频率 | % | 相对基准频率的性能百分比 |
| 内存可用量 | MB | Available MBytes |
| 已提交量 / 提交上限 | MB | 判断提交压力与页面文件压力 |
| 页面文件使用率 | % | Paging File `% Usage` |
| 硬缺页速率 | 次/秒 | Pages Input/sec |
| 磁盘总占用率 | % | PhysicalDisk `% Disk Time` |
| 磁盘平均响应 | ms | Avg. Disk sec/Transfer |
| 系统处理器队列 | 个 | Processor Queue Length |
| 全局定时器抖动 | ms | 16ms 高精度定时器的实际延迟 |

- **规则**：常规 1 秒采样一次；游戏模式 200 毫秒采样一次。200ms 采样只更新轻量指标（CPU、内存、抖动、前台进程），磁盘与进程排行仍按 1 秒更新。
- **验收**：CPU / 内存与任务管理器偏差 ≤ 5%；时间戳严格单调递增；游戏模式连续 10 分钟无采样缺口（允许 ≤ 0.1% 丢点）。

#### FR-003 GPU 与显存采集

- **描述**：采集 GPU 总占用、每进程 GPU 占用、专用显存与共享显存；M3 增加温度、功耗、频率。
- **规则**：
  - M1 使用 PDH `GPU Engine` 与 `GPU Adapter Memory` / `GPU Process Memory` 计数器，支持多适配器。
  - 每进程 GPU 占用按 `pid` 聚合 3D / Copy 引擎，单进程上限按 100% 归一。
  - M3 接入 NVML（NVIDIA）、ADL（AMD）、IGCL（Intel）；任一厂商初始化失败时自动降级为 PDH 数据，界面缺失字段显示 "—"，不得崩溃或阻塞采样。
  - 厂商 SDK 调用固定在 1 秒节拍，单次调用超过 200ms 则判定该厂商数据降级并退避 10 秒。
- **验收**：GPU 总占用与任务管理器偏差 ≤ 10%；混合显卡（核显 + 独显）能分别显示；拔掉独显或驱动异常时仍可运行；M3 温度/功耗数值与厂商工具偏差 ≤ 5%。

#### FR-004 进程级资源排行

- **描述**：每个 1 秒采样点记录 CPU、GPU、专用工作集、IO 排名前 5 的进程；前台进程始终包含。
- **规则**：
  - 记录 PID、进程名、启动时间（用于识别 PID 复用）、CPU%、GPU%、工作集、私有字节、IO 速率。
  - 无法读取的受保护进程显示为"受保护进程"，不因此中断采集。
  - 进程名截断到 64 字符，避免超长路径。
- **验收**：排行结果与任务管理器同口径偏差 ≤ 10%；PID 复用不会把新旧进程数据混在一起；单次进程采样耗时 ≤ 10ms。

#### FR-005 实时时间轴

- **描述**：以时间为横轴，叠加 CPU、GPU、内存、显存、磁盘等曲线；卡顿事件以标记形式落在时间轴上，点击可查看窗口内详情。
- **规则**：
  - 数据窗口默认 15 分钟，支持 1 / 5 / 15 分钟缩放与拖动。
  - 多条曲线共用同一时间轴；悬停显示该时刻全部指标与前台进程。
  - 数据降采样采用每像素列 min/max，保证尖峰不被抹掉。
  - 主窗口最小化或隐藏时停止图表渲染，恢复时补绘。
- **验收**：15 分钟数据首次渲染 ≤ 300ms；缩放/拖动交互响应 ≤ 100ms；悬停数值与原始采样点一致；隐藏时 UI 进程 CPU 占用 ≤ 0.1%。

#### FR-006 卡顿判定

- **描述**：融合三类信号判定卡顿，并支持全局热键手动标记。
- **信号与默认阈值**：

| 信号 | 默认阈值 | 说明 |
| --- | --- | --- |
| 定时器抖动 | 单次 ≥ 50ms 记疑似；≥ 100ms 直接确认 | 16ms 高精度定时器的实际唤醒间隔减去 16ms |
| CPU 尖峰 | 前台进程 ≥ 2.5 倍基线且 ≥ 30% 单核；系统 ≥ 85% | 基线为最近 30 秒中位数 |
| GPU 尖峰 | GPU 总占用 ≥ 85% 且较基线上升 ≥ 20 个百分点 | 需 PDH GPU 数据可用 |
| 内存压力 | 可用内存 < max(1GB, 8%) 或提交率 > 90% | 两者任一 |
| 磁盘压力 | 平均响应 ≥ 50ms 或占用率 ≥ 95% 持续 2 秒 | M2 纳入评分，默认不单独确认事件 |

- **规则**：
  - 3 秒内出现的多个信号合并为同一事件；事件结束后静默 2 秒再结束；冷却 5 秒内不重复建事件。
  - 事件包含开始时间、结束时间、持续时长、综合评分（0–100）、命中的信号与峰值。
  - 手动热键标记必然生成事件，评分记为 100，来源标记为"手动"。
  - 阈值全部可在设置中调整，修改后立即生效。
- **验收**：用测试工具制造 CPU 满载、内存耗尽、GPU 满载、磁盘高延迟，每种场景检出率 ≥ 90%；10 分钟静置 0 误报；事件从发生到界面可读 ≤ 2 秒。

#### FR-007 会话记录与回放

- **描述**：事件确认后，把事件前后各 30 秒数据写成一个会话文件；用户可在界面中重新打开回放。
- **规则**：
  - 文件格式为 gzip 压缩的 JSONL，包含头部元信息、系统采样、进程采样、事件、归因报告、尾部校验。
  - 先写临时文件，`FlushFileBuffers` 后原子重命名；异常退出不得留下被识别为有效会话的半文件。
  - 会话目录 `%LOCALAPPDATA%\AzureGameAssistant\sessions\`，最多保留 20 个文件或 500MB，超出按时间淘汰。
  - 同一事件重复触发时只保存一次。
- **验收**：卡顿后 3 秒内文件可被列表发现；文件可被工具重新打开且时间轴一致；人为强杀进程后目录中无损坏会话；留存策略生效。

#### FR-008 归因报告

- **描述**：对事件窗口内的数据做归因，给出主因分类、可疑进程、置信度与建议。
- **主因分类**：CPU 抢占、GPU 瓶颈、显存不足、内存压力、磁盘瓶颈、系统调度/驱动、未知。
- **规则**：
  - 可疑进程按 CPU / GPU / 内存 / IO 的变化幅度加权排序，最多列 3 个。
  - 结论必须基于事件窗口数据，使用"疑似 / 可能"等限定词，不得给出无证据的断言。
  - 建议为 1–3 条，可执行且不包含自动修改系统的操作。
  - 报告随界面语言生成中文或英文。
- **验收**：内置 5 类归因测试场景分类准确率 ≥ 90%；报告不含空结论（"未知"也必须给出下一步排查建议）；报告可在会话回放中复现。

#### FR-009 全局热键标记

- **描述**：默认 `Ctrl+Alt+M`，用户可修改；按下后立即把"此刻之前 30 秒 + 之后 30 秒"保存为手动事件。
- **规则**：注册失败（冲突）时在设置中提示并允许改键；游戏全屏独占可能拦截系统热键，需在帮助中说明该限制。
- **验收**：桌面与无边框全屏游戏中热键有效；冲突时给出明确提示；连续按 3 次生成 3 个独立事件（受冷却合并规则约束）。

#### FR-010 游戏自动识别

- **描述**：识别前台全屏程序，自动进入 200ms 高频采样，退出全屏 10 秒后恢复 1 秒。
- **规则**：
  - 判定组合：`SHQueryUserNotificationState` 返回 `QUNS_RUNNING_D3D_FULL_SCREEN`，或前台窗口覆盖所在显示器 ≥ 95% 且进程不是桌面/任务栏/系统外壳。
  - 内置浏览器、视频播放器排除名单，避免网页全屏视频误判；用户可在设置中增删名单。
  - 切换状态不打断已有事件，不重启采集进程。
- **验收**：主流游戏（至少 5 款，覆盖 DX11 / DX12 / 无边框窗口）识别率 ≥ 90%；浏览器全屏视频不触发；桌面右键全屏窗口不误判。

#### FR-011 托盘与通知

- **描述**：托盘图标常驻，悬停显示实时 CPU / GPU / 内存；右键菜单包含：打开主界面、标记卡顿、暂停/恢复监控、静音通知、设置、退出。
- **规则**：卡顿事件使用托盘气泡提示，点击打开事件详情；可在设置中关闭通知；通知内容不包含进程完整路径等敏感信息。
- **验收**：菜单项状态与监控状态一致；暂停后不再产生新事件但保留已有数据；退出后托盘图标消失。

#### FR-012 桌面悬浮条

- **描述**：M3 提供可选的置顶小条，显示 CPU / GPU / 内存实时数值与一个迷你曲线。
- **规则**：可拖动、可调透明度、可切换鼠标穿透；位置按显示器记忆；不抢焦点；关闭时立即释放相关资源。
- **验收**：开启后界面进程内存增量 ≤ 8MB；不抢占游戏焦点；多显示器下位置正确恢复；关闭后无残留置顶窗口。

#### FR-013 中英双语与明暗主题

- **描述**：界面支持简体中文与英文运行时切换；主题支持跟随系统、浅色、深色。
- **规则**：所有界面文案走资源文件，不硬编码；语言与主题切换无需重启；默认跟随系统，视觉风格极简，仅保留曲线、数值、事件列表必要元素。
- **验收**：两种语言下无缺失文案；切换语言/主题 ≤ 300ms；系统切换深浅色后 1 秒内界面跟随。

#### FR-014 设置管理

- **描述**：设置项包括采样频率、卡顿阈值、热键、开机自启、会话留存、语言、主题、通知、游戏排除名单、厂商 GPU 开关。
- **规则**：保存为 `%LOCALAPPDATA%\AzureGameAssistant\settings.json`，带 `schemaVersion`；文件损坏时备份原文件并回退默认值，不得阻止启动。
- **验收**：修改即时生效（标注需重启的除外）；损坏设置文件可自动恢复；默认值与本文档一致。

#### FR-015 报告导出

- **描述**：把单个会话导出为 Markdown 报告与时间轴 PNG 截图。
- **规则**：导出完全本地，由用户选择保存路径；文件名包含事件时间与主因；报告包含环境摘要、事件时间轴、指标峰值、可疑进程、建议。
- **验收**：导出的 Markdown 在常见编辑器可正常显示；PNG 包含时间轴与事件标记；导出后无网络请求。

#### FR-016 日志与诊断

- **描述**：采集进程与界面进程分别写滚动日志，保留最近 5 个文件、每个 2MB；设置中提供"打开日志目录"。
- **规则**：默认 Info 级别；不记录进程完整路径、用户名、IP 等不必要信息；写盘失败不得影响采集。
- **验收**：日志可定位启动、降级、错误原因；滚动策略生效；关闭日志后不再写盘。

#### FR-017 单实例与异常恢复

- **描述**：采集进程与界面进程各保证单实例；界面进程检测到采集进程退出时自动重启（退避 1s / 5s / 15s，最多 3 次）。
- **规则**：使用命名互斥体；采集进程崩溃时写入崩溃摘要；重启后环形缓冲从空开始，不拼接损坏数据。
- **验收**：重复启动只保留一个实例；强杀采集进程后 5 秒内恢复采集；连续失败 3 次后停止重试并在界面提示。

#### FR-018 权限降级

- **描述**：默认以普通用户权限运行；部分受保护进程或厂商数据不可用时，功能降级但不崩溃。
- **规则**：界面顶部显示降级提示与"以管理员身份重启"入口；不得自动提权，不得弹出 UAC 骚扰；提权后界面与采集进程必须同权限运行。
- **验收**：普通权限下完成核心采集与归因；受保护进程显示占位信息；提权重启后数据完整；混合权限场景给出明确提示。

## 9. 性能验收方法

1. 使用 Release 构建，关闭调试器、关闭 Visual Studio 诊断工具。
2. 测量环境：Windows 11 最新正式版，SSD，至少 8 逻辑处理器；记录 CPU / GPU / 内存型号。
3. 内存：稳定运行 10 分钟后，用 PowerShell 读取 `WorkingSet64` 与 `PrivateMemorySize64`，重复 3 次取中位数；以专用工作集为准。
4. CPU：记录 10 分钟内 `TotalProcessorTime` 增量，按 `增量 / 实际时长 / 逻辑处理器数 × 100%` 计算整机占比。
5. 磁盘：用性能监视器记录进程 `IO Write Bytes/sec`，静置 10 分钟取平均。
6. 游戏模式：用至少 2 款游戏各运行 10 分钟，重复上述测量；同时确认无采样缺口。
7. UI 内存：分别测量"仅托盘""悬浮条开启""主窗口显示 15 分钟数据"三种状态。
8. 任何一项超出 NFR 目标即视为不通过，须在发布前修复或在交接文档中记录豁免理由。

## 12. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| PDH GPU 计数器在不同驱动/系统上实例名与精度不一致 | GPU 曲线缺失或偏差大 | 以 English counter 名注册；解析失败时降级为"不可用"；M3 用厂商 SDK 补足 |
| 厂商 SDK（NVML / ADL / IGCL）接口或 DLL 随驱动变化 | 初始化失败、采样线程卡住 | 全部动态加载；独立线程 + 200ms 超时；失败退避并降级，不影响主流程 |
| 卡顿判定误报/漏报 | 用户不信任结论 | 阈值可调；默认保守；事件必须附带命中信号；用测试工具建立回归集 |
| 内存红线 30MB 难以达成（PDH 通配符实例多） | 违反核心卖点 | 采集进程 AOT、预分配缓冲、进程信息走 NT API；GPU 通配符 1 秒一次；用预算测试卡住每个 PR |
| WPF 界面内存超 80MB | 违反体验目标 | 自绘图表、禁用重型图表库、隐藏时停止渲染、限制历史缓存 |
| 全屏独占游戏拦截全局热键 | 手动标记失效 | 文档说明限制；提供托盘/悬浮条入口；后续评估低级键盘钩子（需评估反作弊风险，v1 不做） |
| 反作弊误判 | 用户账号风险 | 不注入、不 Hook、不读写游戏内存；仅调用系统计数器；发布前明确声明 |
| 中文/英文文案遗漏 | 体验不完整 | 资源键审查 + 启动时检查缺失键；CI 加静态检查（后续） |
